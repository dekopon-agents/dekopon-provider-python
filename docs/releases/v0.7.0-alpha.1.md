# Python provider v0.7.0-alpha.1

This **prerelease** combines RustPython 0.5.0 with bounded in-memory DataFusion 55.1 SQL (`dekopon_tables.query(sql, tables)`) and ndarray 0.17.2 / statrs 0.19.1 / SmartCore 0.6.14 numeric operations (`dekopon_numeric`). It supports registered record batches, joins/grouping/windows and a small vector/matrix/statistics/regression/explicitly seeded clustering facade. It is **not** NumPy, pandas, scikit-learn or notebook parity: foundation/extraction/reporting modules, CSV/Parquet file scans, persistent tables/models, asset I/O and PDF/XLSX/charts remain out of scope. No Turso, disk spill or new Python filesystem/socket authority was added. Existing broker-granted HTTP and JSON result ceilings remain.

**Runtime prerequisite: not compatible with the currently deployed broker.** In addition to existing HTTP 1.1, this component imports `dekopon:clock/monotonic@1.1.0`, `dekopon:clock/wall@1.1.0` and `dekopon:random/source@0.1.0`. The required host implementation is the **unreleased** [core PR #354](https://github.com/dekopon-agents/dekopon/pull/354), pinned in this provider to commit `820ee7a521201828ed42171f1ead5e75026595d2`. Missing imports fail closed when loading the component; this prerelease does not deploy or release that host. SQL uses wall time for statement-stable timestamps; it does not expose Python `datetime.now`.

**Resource qualification is limited.** Combined SQL/numeric scripts ran through the candidate broker host with *configured* 256 MiB per linear memory, 8 billion fuel and 30 seconds per invocation. Existing pure Python/HTTP tests ran with 64 MiB, 1 billion fuel and 5 seconds; **SQL/ML at the default 64 MiB runtime profile and Raspberry Pi performance are not proven**. The component's file size is **not** guest heap use or measured RSS, and DataFusion's 8 MiB query pool is not a total allocation cap. Do not treat this as an approved production memory or deployment profile.

Sources: [provider PR #14](https://github.com/dekopon-agents/dekopon-provider-python/pull/14), [DataFusion 55.1 no-JS fork PR #1](https://github.com/dekopon-agents/datafusion/pull/1), fork commit `cf3778098ad3ea283ecd8ee2a991be7d9a29750c`. The attached component, checksum and SBOM are produced and verified by the supported release workflow; use the release asset checksum rather than a developer-machine artifact digest. The stable release and stable OCI/latest aliases are not replaced by this prerelease. There is **no production deployment** in this release.
